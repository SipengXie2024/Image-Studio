# 用户可控的品味学习闭环

这个分支把批次生成结果变成可复用的显式反馈，但不会在后台改写用户的生图提示词。

## 用户操作如何被记录

- **选定**：把当前图片记录为正向图片判例，不要求填写原因。
- **选定并提建议**：把当前图片记录为正向判例，逐字保存建议，并进入编辑模式。建议不会被模型预先改写。
- **全部不满意**：把本批图片记录为负向判例。原因可以留空；填写原因时，原文会成为一个待确认的长期规则候选。

普通的图片点击只表示查看，不会被当作喜欢。反馈事件和规则决策采用只追加记录，避免历史偏好被静默覆盖。

## 系统如何变得更符合品味

后续批次的 AI 评审会同时参考：

1. 最近明确选定或否定的图片判例；
2. 用户亲自批准的长期评审规则；
3. 当前批次的原始提示词。

长期规则默认处于待确认状态。只有用户批准后才进入 critic；规则不会注入生成提示词。

对未明确要求多人或多视图的角色类任务，critic 会把多主体、角色重复描绘、拼版或多视图结果直接标记为不合格，不允许它们进入 top-3。若合格图片不足，系统只补抽一轮，并继续使用完全相同的已提交提示词。

用户仍可查看不合格图片并显式选择它，避免自动门槛替用户做不可撤销的决定。

## 原提示词保证

每个新结果都会保存 `originalPrompt`、`submittedPrompt` 和来源信息。没有显式用户控制产生的附加内容时，提交前会校验两者字节一致。风格、标注、编辑建议或“优化提示词”等已有显式操作仍由用户主动触发。

## 从旧历史启动

旧版历史没有可靠记录“选定、拒绝或喜欢”，因此启动层不会把旧 prompt、模型改写后的 prompt、保留或删除行为推断成偏好。它只把历史中的显式风格标签和负向提示词展示为“曾请求过”的弱候选，逐条由用户采纳或忽略；“稍后再说”会延后七天。

旧历史仍存放在原有 `image-studio` IndexedDB 中；反馈、候选决策和品味画像单独存放在 `image-studio-taste` IndexedDB 中。API Key、令牌和其他敏感字段不进入品味数据库。

Windows 迁移逻辑同时识别旧版 `%LOCALAPPDATA%\image-studio\WebView2\EBWebView\Default` 数据目录，以免首次运行新版时漏掉旧历史。

## 当前边界

- 品味学习只影响排序、淘汰和补抽，不训练或微调模型。
- 无文字原因的选择仍能作为图片判例，但不会凭空生成自然语言规则。
- 自动评审需要配置可处理图片的 Responses 渠道；未配置时正常生图不受影响，可稍后手动重试评审。
- 旧历史最多保留应用当前的历史上限，无法恢复此前已经物理删除的记录。
